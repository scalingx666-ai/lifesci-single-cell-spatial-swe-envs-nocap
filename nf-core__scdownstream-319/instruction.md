# Issue

**Title:** Use log1p normalisation in per-label pipeline nf-tests

## Description

The two per-label pipeline nf-tests in `tests/main_pipeline_sub_integrate_per_label.nf.test` were the slowest jobs in the nf-test CI after the default test. In [run 36313500660](https://github.com/nf-core/scdownstream/actions/runs/36313500660) they took 923 s (shard 6/7) and 983 s (shard 7/7). About 10.5 min of each was `SUB_INTEGRATE:NORMALIZATION:SCRAN_NORMALIZATION` on `extension_base/merged.h5ad`, which has 32,135 cells.

These tests check per-label integration and the label whitelist, and neither depends on scran. This PR sets `normalization_method = 'log1p'` for both tests. `SCRAN_NORMALIZATION` keeps its coverage from its module test and from the default pipeline test.

The only snapshot change is that the versions YAML now lists `SCANPY_LOG1PNORM` instead of `SCRAN_NORMALIZATION`. The snapshot was regenerated locally with apptainer and confirmed stable by a second `--ci` run.

Expected effect: pipeline shards 6/7 and 7/7 should drop from about 16 to 17 min to about 6 min. The overall CI wall time barely changes, because the default test (about 16.5 min on shard 1/7) is now the critical path.
