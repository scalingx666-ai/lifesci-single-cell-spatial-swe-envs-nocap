# Issue

**Title:** Speed up CI and local tests: two-tier nf-test, sized test resources

## Description

This PR re-proposes the nine `ci-speedup` commits (`ffcfd53b..a9342200`) that were pushed to `dev` by accident and reverted in #316. It shortens nf-test CI and local pipeline tests by splitting CI into two tiers and sizing test resources per process.

The base is `revert-ci-speedup-push` so the diff shows only these changes. After #316 merges, retarget this PR to `dev`; GitHub retargets it automatically if the `revert-ci-speedup-push` branch is deleted on merge.

## Changes

Two-tier nf-test CI in `.github/workflows/nf-test.yml`:

- The `nf-test` job (tags `modules_local,subworkflows_local`) runs on 4-CPU runners with up to 25 shards.
- The new `nf-test-pipeline` job (tag `pipeline`) runs on `16cpu-linux-x64`, one test per runner.
- `confirm-pass` needs both jobs.

Tests and test profile:

- Add the missing local tags to the `celldex/fetchreference` and `singler` module tests and the `singler` subworkflow test.
- Fold `main_pipeline_build` into `default`. `-profile test` adds `seurat` to `integration_methods` and uses the `Adult_COVID19_PBMC` CellTypist model. The build test never ran `deviance`, which the module and subworkflow tests still cover.

`SCRAN_NORMALIZATION`:

- `computeSumFactors` uses `MulticoreParam(task.cpus)`; the size factors are bit-identical.
- The module test uses `SRR28679759_filtered_matrix.h5ad` (7,373 cells), which drops its runtime from 16-27 min to about 65 s. The slow step is the merge step of scran `quickCluster`, which takes about 1300 s at 38k cells.

`conf/test_resources.config`:

- Sets per-process CPU and memory from measured peak RSS, scoped to `NFCORE_SCDOWNSTREAM:*` so module and subworkflow tests keep their defaults.
- Is included from `conf/test.config`.
- Keeps `resourceLimits` at 4 CPU and 15 GB.
